# UI 规范（第 4 轮：认领即归属 + 独立认领屏 + 图片滑动）

逐轮收紧：**让操作尽可能少，让每一屏尽可能空，让空的一屏居中。**

## 0.0 第 4 轮新增（认领即归属）

1. **认领是独立一屏** `/items/[id]/claim`：详情页只放一个「这是我的，我要认领」按钮，点了**跳转到独立屏幕**填姓名与手机号；不要再做成详情页里的内联卡片。
2. **认领即归属**：提交成功 → 物品立刻变「已认领」+ 整屏对勾 → 回到详情页看揭晓的联系方式/位置。
3. **已认领仍留在墙上**，卡片带「已认领」角标；状态徽标统一用 `ITEM_STATUS_LABEL`（寻找失主中 / 已认领 / 已撤单）。
4. **撤单只在被认领之前**：`/me` 的「撤单」按钮只在 `published` 时出现。
5. **图片可左右滑动**：详情页相册支持 `drag="x"` 滑动切图（阈值 ±60px 或 ±400px/s），左右按钮与圆点**必须保留**（无障碍 + E2E 都依赖）。
6. **文案：领取 → 认领。** 「我要认领」「认领人」「我的认领」「确认认领」。

## 0. 第 3 轮新增的四条

1. **内容量不大的页面要居中**：内容块用 `my-auto`（不要用 `justify-center`，后者在小屏会裁掉顶部内容），
   连同底部主按钮一起在剩余空间里垂直居中。适用：`/publish` 第 1 屏（无照片时）与第 3 屏、首页空态、`/me` 空态、登录注册。
   列表类页面不要居中。
2. **每拍完一张照片就给建议**：AI 判断当前这组照片能不能直接用，给出「可以直接用」或「建议补拍」+ 一句话理由（≤20 字）。
   - 建议补拍时，底部并排两个按钮：**「继续拍照」**（次要）+ **「下一步」**（主要）。
   - 通过时只有 **「下一步」** 一个主按钮（加照片走计数器那行的「继续添加」）。
   - 建议只是建议，**永远不阻塞**：`下一步` 任何时候都可点。
3. **AI 写描述时全屏加载**：用 `LoadingOverlay`（带呼吸动画）。
   加载期间**不要同时渲染表单**——第 2 轮就是这里出错，骨架屏和输入框同时出现，屏上出现两套输入框。
   加载结束再渲染填好的表单让用户改。
4. **文案继续变短**：见 §3。

## 1. 四条硬约束

1. **没有底部导航栏。** 全站唯一的「我的」入口在首页右上角（`AppHeader showMe`，`data-testid="me-entry"`）。
   其他页面用「返回」回到上一屏，不要新增导航。
2. **一步一屏。** 任何需要多步的操作必须拆成独立屏幕，每屏只问一件事，主按钮只有一个。
   禁止把长表单和拍照放在同一屏。
3. **文案尽量短。** 详见第 3 节。一句话说清；能用 6 个字就不用 20 个字；不解释系统内部机制。
4. **动效给正反馈，不给负担。** 统一用 `motion`（`motion/react`），只用下面这份词汇表。

## 2. 信息架构

| 路由                | 一屏只做一件事                                                        |
| ------------------- | --------------------------------------------------------------------- |
| `/`                 | 浏览失物墙。顶部：标题 + 右上角「我的」；一个发布按钮；下面双列瀑布流 |
| `/publish`          | 三步向导：**拍照（含 AI 建议）→ 确认信息（全屏加载）→ 怎么还**        |
| `/items/[id]`       | 看这一件物品（图片可左右滑动）；底部一个「我要认领」入口              |
| `/items/[id]/claim` | **独立认领屏**：只填真实姓名 + 手机号，一个主按钮                     |
| `/me`               | 两个标签页：**我的发布** / **我的认领**（不要同屏堆两段列表）         |
| `/login`、`/signup` | 一张卡、一个主按钮                                                    |

## 3. 文案规则

- 标题 ≤ 8 字。说明文字最多一句，≤ 20 字，能在界面上读出来就不要再解释一遍。
- 不写「系统会自动……」「便于……」「请注意……」这类说明性从句；需要时用一句短提示代替。
- 删除所有的免责声明式段落。必须保留的隐私/实名提示压到一行小字。
- 按钮用动词短语：「拍照 / 选择照片」「下一步」「发布」「我要认领」「确认认领」「撤单」。
- 不要「点击」「按钮」「页面」等指代 UI 的词。

## 4. 动效词汇表（唯一出入口：`@/components/motion/primitives`）

```ts
;DURATION.fast | base | slow // 0.18 / 0.26 / 0.42 秒
FadeIn // 区块淡入上移
StaggerList / StaggerItem // 列表依次入场
TapScale // 点击缩一下（仅客户端岛）
StepTransition // 一步一屏的左右滑动（stepKey + direction）
Collapse // 展开/收起（高度自适应）
SuccessOverlay // 成功后整屏对勾（强烈正反馈）
LoadingOverlay // 全屏等待态（呼吸动画 + 三点）
MotionBar // 进度条平滑推进
PageTransition // 已由 app/template.tsx 全局挂好，页面里不要再用
```

规则：

- 时长只用 `DURATION` 里的值；曲线用 `EASE_OUT`。不要写自定义 spring（`SuccessOverlay` 内部那个除外）。
- 位移 ≤ 24px，缩放 ≥ 0.95。不要做旋转、弹跳。
- **无限循环只有一个例外**：`LoadingOverlay` / 加载指示器必须持续运动，否则用户会以为卡死。
  其它任何地方禁止 `repeat: Infinity`。
- 卡片这类 Server Component 优先用 CSS：`active:scale-[0.98]`、`transition-shadow`，不要为了动效把组件变成客户端组件。
- 无障碍已由 `MotionProvider`（`reducedMotion="user"`）统一处理，不需要在业务代码里判断 `useReducedMotion`。
- 动效不得影响可测试性：元素必须始终存在于 DOM 里（用 opacity/transform，不要用 `display:none` 做入场）。
  断言用的 `data-testid` 不要挂在会卸载的容器上。

正反馈出现的位置（必须有）：

1. 发布成功 → `SuccessOverlay`（约 0.9s）→ 跳回首页；
2. 领取提交成功 → `Collapse` 展开揭晓卡片；
3. 撤单 → toast + 该卡片淡出（撤单后物品从「我的发布」列表消失）；
4. 照片上传完成 → 缩略图弹入；
5. 步骤切换 → `StepTransition`；
6. 墙上首屏卡片 → `StaggerList` 依次出现；
7. 每张照片上传完成 → 建议卡片 `FadeIn` 出现（检查中 / 通过 / 建议补拍 三态）；
8. 认领提交成功 → `SuccessOverlay`（`testId="claim-success"`）→ 回详情页揭晓联系方式/位置。
